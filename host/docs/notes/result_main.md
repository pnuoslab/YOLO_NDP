3. **q100은 거의 무손실**(darknet 기준 −0.40). JPEG 손실은 q85에서 생긴다.
4. **darknet 커널은 정확하지만 target에서 2.5~3배 느려서 NDP가 Baseline보다 느려진다**(0.41~0.65배). 1080p MOT 입력에서는 정확도와 속도가 맞바뀐다. (4K에서의 darknet 커널 속도는 이번 매트릭스에 없다 — E3은 MOT 시퀀스만.)

## 3. 주의해야 할 측정상의 문제

### 3-1. ⚠️ 샘플링 조건은 단계 합으로 비교하면 틀린다
Baseline이 건너뛴 프레임을 `consume_frame()` 으로 디코딩하는 시간이 `host_pre` 타이머 밖이다. 그래서 sr>1에서 Baseline 단계 합이 과소평가된다. MOT20-02 sr=5: 단계 합 기준 NDP가 0.95배(느림)로 나오지만, 이는 Baseline 쪽에 일부 비용이 빠진 결과다. 1080p 합성 영상 sr=5에서는 단계 합 0.78배 vs wall 1.26배로 결론이 뒤집혔다. **샘플링 표는 wall e2e로 만들거나, 타이머를 고쳐 sr>1만 다시 재야 한다.**

### 3-2. AV1의 target 디코딩은 과구독 상태
target이 `libdav1d` 를 `thread_count=0` 으로 써서 14코어 affinity에 수십 스레드가 몰린다(target 보고서 §6-3). E5의 AV1 수치에 그 영향이 들어 있다.

### 3-3. NDP JPEG 모드의 host CPU는 부풀려져 있다
host CPU 약 230 s 중 대부분이 OpenCV 작업자 스레드의 busy-wait로 보인다(raw 모드는 39 s). CPU를 논문 지표로 쓰려면 `cv::setNumThreads()` 를 고정해 다시 재야 한다.

### 3-4. 비결정적 조건 하나: MOT20-03 + darknet 커널
다른 모든 조건은 반복 3회의 mAP가 완전히 같은데, **MOT20-03 darknet-q85만 0.39pp, darknet-raw는 0.001pp 흔들렸다.** MOT20-03은 폭이 홀수(1173)여서 1174로 패딩한 유일한 입력이다. target의 darknet 커널이 홀수/패딩 폭에서 경계 처리가 비결정적일 가능성이 있다(**추정**). 크기가 작아 결론은 바뀌지 않지만 target 쪽 확인 대상이다.

### 3-5. 측정 하네스의 결함 2건 — 해결됨, 데이터 손실 없음
본측정 중 `collect_row.py` 가 target 필드를 `results.csv` 에 넣지 못하는 것을 발견했다(헤더가 첫 행으로 고정 / 줄 중간 태그 미인식). 원시 파일이 실행마다 온전히 남아 있어 `rebuild_results.py` 로 357행 전부를 재조립했고, 측정이 끝난 뒤 `collect_row.py` 자체도 고쳤다(`522ba46`). 지금 `results_full.csv` 가 정본이다.
