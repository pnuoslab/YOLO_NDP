## 읽는 법

1. **정확도는 사실상 같다.** mAP 차이가 4개 시퀀스에서 0.03pp 이하, MOT20-03만 −0.22pp다. 사람 단위로도 BASE가 잡는 934명 중 NDP가 놓치는 사람은 **3명(0.3%)** 이고, 그 3명은 BASE도 전 프레임에서 **1번씩만** 잡던 사람이다. 반대 방향으로는 NDP만 잡는 정답 박스가 더 많다(0.56% vs 0.33%) — 프레임 재현율은 NDP가 오히려 0.23pp 높다.
2. **샘플링의 효과도 두 파이프라인에서 같다.** 1/5에서 추가 누락 36명 vs 37명, 1초 초과 지연 105명 vs 100명. 파이프라인 구조의 차이가 샘플링 손실을 키우거나 줄이지 않는다.
3. **완전히 같지는 않다.** 박스가 거의 항상 sub-pixel 단위로 다르다(IoU 0.995, 동일 박스 1개). 방향성 없는 작은 차이이므로 위치 어긋남(sws 커널에서 본 것)이 아니라 **수치 차이**로 보인다. 남은 구조적 차이 후보는 (a) target이 축소 결과를 **8bit RGB로 양자화해 보내는 것** — Baseline은 float 그대로 신경망에 넣는다 — 과 (b) YUV→RGB 변환 구현의 차이다. H.264 디코딩 자체는 표준상 비트 단위로 같아야 한다(**추정** — 픽셀을 직접 비교하지는 않았다).
4. **MOT20-03의 −0.22pp**는 다른 시퀀스보다 크다. 이 시퀀스는 darknet 커널 조건에서만 반복 간 mAP가 미세하게 흔들린 유일한 경우였고(`result_main.md` §3-4), 폭이 홀수(1173 → 1174 패딩)인 유일한 입력이다. 패딩 열 근처의 경계 처리 차이일 가능성이 있다(**추정**).

## 결론

**JPEG와 리사이즈 커널을 Baseline과 맞추면, 전처리를 storage로 옮기는 것만으로는 정확도도 사람도 잃지 않는다.** 배포 구성(sws + q85)의 손실(사람 5.8%, 재현율 −8.8pp, `result_03a_person.md`)은 전부 리사이즈 커널과 JPEG에서 나온다. 단, 이 구성은 target 리사이즈가 느려서 1080p MOT 입력에서는 Baseline보다 느리다(0.46~0.65배, `result_main.md` §1) — 정확도와 속도가 맞바뀌는 지점이다.
