## §4-0 검증 — **통과**

### 4-0.1 mAP 재현 — 통과 (75/75, 최대 |Δ| 0.0308 pp)

`src/detector.c` `vmap_compute_map()`과 같은 알고리즘을 Python으로 구현했다: 신뢰도 하한 0.005, 탐지는 덤프 줄 순서(= C의 `qsort` 결과, §2-2), 탐지마다 같은 프레임 정답 중 IoU 최대(동점이면 앞 번호), `IoU > 임계값`(엄격), 정답당 1회 매칭, `-points 101`(`run_all.sh`가 전달). YOLO 라벨 파일(C가 읽은 것과 같은 파일)을 정답으로 썼다.

| 항목 | 값 |
|---|---|
| 대상 | MOT 덤프 75개 전부 |
| mAP@0.5 최대 \|Python − C\| | **0.0308 pp** (MOT17-09 darknet-raw sr1). 허용 ±0.05 |
| mAP@[.5:.95] 최대 \|Python − C\| | 0.0178 pp |
| 차이 분포 (mAP@0.5) | ≤0.001: 56개, ≤0.01: 16개, ≤0.05: 3개, >0.05: 0개 |

**첫 시도는 실패했고, 원인을 확정한 뒤 통과했다.** 첫 계산에서 MOT17-09 BASE sr=5가 **+0.0706 pp**로 허용치를 넘었다. 명세대로 원인을 찾을 때까지 멈췄다.

| 의심한 원인 | 확인 결과 |
|---|---|
| 정답 필터·좌표계·프레임 오프셋 | 같은 시퀀스 sr=1이 Δ 0.0000 → 아님 |
| 입력 개수 | 프레임 105·탐지 7,480·정답 750 모두 C 로그(`eval frames = 105, detections = 7480, unique GT boxes = 750`)와 같음 |
| 샘플링 | sr=5 탐지가 sr=1 같은 프레임 탐지와 7,480행 전부 동일 |
| 덤프 반올림(박스 소수 둘째 자리) | 좌표를 ±0.005 px 범위에서 40회 흔들어도 값 불변 |
| 정렬·동점·하한·라벨 파일·AP 변형(11점, AUC, `>=`, 정답 수 ±1) | 어느 것도 C 값 재현 안 함 |
| TP/FP 하나, IoU 경계 3개 이하 조합 | 7,480개 전수 탐색, 재현 안 함 |

그래서 **사용자 허락을 받아 진단 실행을 했다.** 저장소를 scratch 폴더에 복사해 덤프에 C 내부 값(탐지별 `max_iou`, 배정 정답 번호, 반올림 전 박스·신뢰도)을 추가로 쓰게 한 별도 빌드를 만들고, 로컬 영상 사본으로 같은 조건을 돌렸다. 측정용 `./darknet`(04:17 빌드, sha256 `c7cfcc3c…`)은 바뀌지 않았다. 결과:
1. 진단 실행의 탐지는 측정 덤프와 **바이트 단위로 같고**(앞 7열), mAP도 같은 89.75 %다.
2. **탐지별 판정(배정 정답, IoU)은 7,480개 전부 Python과 같다.**
3. C 자신의 판정과 순서를 넣어 C 루프를 그대로 옮겨도 **89.8180**이 나온다 — 측정값 89.7474가 아니다.
4. 같은 C 함수를 떼어 내 컴파일하면: `-O2` → **89.8180**, `-O2 -freciprocal-math` → **89.7474(측정값과 정확히 일치)**.

→ **원인 (확정)**: 측정 바이너리는 Makefile의 `-Ofast`로 빌드되고, 여기 포함된 `-freciprocal-math`가 101점 재현율 격자 `cur_recall = point * 1.0 / (map_points - 1)`을 `point * (1.0/100)`로 바꾼다. 0.01은 이진수로 정확하지 않아 일부 격자점이 1 ulp 커지고, 재현율이 정확히 그 격자점인 순위에서 `recall >= cur_recall`이 거짓이 되어 다음 순위의 낮은 정밀도가 쓰인다. 나눗셈을 하나씩 바꿔 보면 **격자 계산만** 영향이 있고 정밀도·재현율·평균은 무관하다. MOT17-09 sr=5는 정답이 750개라 `tp/750`이 격자에 정확히 떨어지는 일이 잦아 영향이 가장 컸다.

Python `c_map()`은 이 격자 계산을 따라 하도록 고쳤고(`binary_grid=True`), 정확 산술 값도 함께 기록한다(`summary_map_reproduction.csv`의 `py_ap50_exact`). 남은 최대 0.0308 pp는 격자와 무관하고 허용치 안이라 더 추적하지 않았다(`-Ofast`의 다른 최적화 영향으로 보임 — **추정**).

진단 근거 파일: `~/ndp_analysis/person/diag/` — `diag_build.patch`(진단 빌드에 넣은 변경 25줄), `diag_MOT17-09_BASE_sr5.csv`, `diag_run.log`, `map_fastmath_harness.c`.

## 논문에 쓸 때 주의할 점

1. **"샘플링해도 사람을 놓치지 않는다"고 쓸 수 있는 범위.** 구조적 누락은 1/5에서 0.6%로 매우 적고, 추가 누락(3.9%)도 Baseline이 1~4번만 잡던 경계선 탐지다. 다만 **첫 탐지가 1초 넘게 늦어지는 사람이 1/5에서 11.7%**(최대 17.8초) 있다. "놓치지 않는다"와 "제때 잡는다"는 다른 주장이다.
2. **NDP 배포 구성(sws-q85)의 손실이 샘플링 손실보다 크다.** 트랙 기준 5.8% vs 1/5 샘플링 3.9%, 프레임 재현율 −8.8pp vs −0.5pp. "NDP는 정확도를 잃지 않는다"는 **darknet-raw에만** 성립한다(불일치 0.9%, 위치 IoU 0.995).
3. **손실이 작은 사람에게 몰린다고 쓰면 안 된다.** 순손실은 100~200 px·visibility ≥ 0.75에서 가장 크다. "어려운 사람을 놓친다"가 아니라 "평범한 사람의 박스 위치가 어긋난다"는 쪽이 데이터와 맞는다(원인은 추정 — 박스 이동을 직접 측정하는 후속 분석이 필요하다).
4. **박스 단위 합계는 MOT20-03에 가중돼 있다**(정답의 66%). 시퀀스별 표를 함께 보이거나 시퀀스 평균을 쓰는 편이 공정하다.
5. **임계값을 명시해야 한다.** 손실 크기는 conf 0.1 → 0.5에서 2~4배 변한다(방향은 불변).
6. **C 측정 코드의 mAP에는 컴파일러가 만든 오차가 있다.** `-Ofast`(`-freciprocal-math`) 때문에 101점 격자가 1 ulp 어긋나, 본측정의 mAP 값이 정확 산술보다 최대 0.07 pp 다르다(75개 중 큰 것은 MOT17-09 sr=5 하나). 결론에 영향은 없지만, 정확한 값이 필요하면 `results_full.csv`의 `ap50` 대신 이 분석의 `py_ap50_exact` 열을 쓰거나, C 코드의 비교를 정수식(`tp * 100 >= point * n_gt`)으로 바꾸는 것이 근본 해결이다(측정 코드는 이번에 고치지 않았다).
7. **라벨 모드 덤프에는 사람만 있다**(§2-2). 다른 클래스 분석이 필요하면 라벨 없이 다시 덤프해야 한다.
8. 재현율 절대값(Baseline 35%)이 낮은 것은 yolov7-tiny(416 입력)와 엄격한 기준(conf ≥ 0.25, IoU ≥ 0.5) 때문이다. 이 분석은 **Baseline 대비 상대 손실**을 보는 것이 목적이며, 절대 재현율을 검출기 성능으로 인용하지 않는 편이 좋다.
